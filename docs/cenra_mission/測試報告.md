## 情境一：SPEC §0.1 的九步驟主流程（最重要，這是唯一驗收標準）

| 步驟 | 你要做的操作 | 應該看到什麼 |
|---|---|---|
| 1 | 「今日任務」頁的「選擇業務」選 R100（陳雅婷） | 頁面顯示這位業務的資料 |
| 2 | 看頁面上方 | 「今日固定預約」列出 2 筆（晴天診所 09:30、仁心診所 14:00），可用彈性分鐘欄位有預設值（240） |
| 3 | 看候選任務清單 | 至少各一張攻／守／增任務卡（實際上會看到 8 張：攻2/守3/增3） |
| 4 | 點一張「守」任務卡（例如康泰診所）的「開啟詳情」 | 跳到任務詳情頁，看到三項主要證據（label + 值 + 來源時間） |
| 5 | 審核表單選「修改後採納」，執行方式改成「改成電話」，選一個修改原因，按「送出審核結果」 | 顯示成功訊息，狀態變成「已修改採納」 |
| 6 | 回「今日任務」頁，開一張「攻」任務（例如青禾診所），審核表單選「採納」，送出 | 狀態變成「已採納」（攻任務本來就是電話，這步驟等於示範一次完整採納流程） |
| 7 | 到「行程」頁 | 「電話清單」看到剛剛採納的攻任務和被改成電話的守任務；如果你另外採納了一張「實訪」任務，「實訪清單」會顯示點位順序＋地圖，並看到「拜訪點位與建議順序示意，非即時導航或最佳路線」這行字 |
| 8 | 先在「今日任務」或「行程」頁確認一張已採納的任務被系統標成 scheduled（目前 P0 沒有獨立的「排入行程」按鈕，這張任務出現在「結果回報」頁待回報清單裡就代表已排程）；到「結果回報」頁選 completed／填結果類型／送出 | 顯示更新時間，任務移到「已完成」折疊區塊 |
| 9 | 按瀏覽器重新整理（F5） | 剛剛的審核與結果都還在（不是 session 暫存，是真的寫進 SQLite） |

任務詳情頁在任務被採納／修改後採納後，會多顯示一個「排入今日行程」按鈕，按下去才會把狀態從 `accepted`/`modified` 轉成 `scheduled`，這張任務才會出現在結果回報頁的「待回報」清單。已在瀏覽器實測驗證過。

## 情境二：驗證失敗不能整頁噴錯（SPEC §13.4 要求）

1. 開一張候選任務，審核表單選「延後」，**不要選日期**（如果日期欄位有預設值，這步可能測不出來——可以改測「拒絕」不選原因看行不行）。
2. 送出。
3. **應該看到**：清楚的錯誤訊息（例如「無法送出：defer 必須填 deferred_to」），**不是** Python traceback。
4. 重新整理頁面，確認任務狀態還是「待審核」（沒有部分寫入）。

---

## 情境三：文案護欄（不該出現的敘事）

1. 全程操作中，留意有沒有出現「已被競品入侵」「提升成交率」「路線最佳化」這類字眼。
2. 特別看一下沒有直接競品文字證據的守任務（例如康泰診所、安康診所），文案應該只講「風險待查」，**不能**片面認定是競品造成的。
3. 有明確競品文字的守任務（海碩診所）才會顯示「互動紀錄出現直接競品訊號」這條證據。
4. 自動化上：`pytest tests/test_content_guardrails.py -v` 全綠代表 `app/pages_mission/`、`app/mission_app.py`、`README.md` 都掃過一遍，沒有禁用語句。

## 情境四：CSV 匯出

1. 「今日任務」頁最下面按「匯出今日任務清單（CSV）」。
2. 用 Excel 或文字編輯器打開，確認欄位是 `task_type, target_name, why_now, objective, value_score, action_mode, estimated_minutes, status`，中文不亂碼（檔案是 UTF-8 with BOM）。

## 情境五：重設 Demo（要能一鍵回到初始狀態）

1. 「今日任務」頁最下面「重設 Demo」，**不勾確認框直接按按鈕**：按鈕應該是灰的（disabled），點不下去。
2. 勾選確認框後再按：應該顯示「已重設 Demo 資料」，所有任務卡狀態都變回「待審核」，之前的審核/結果紀錄都清空了。

## 情境六：地圖與電話/實訪分流

1. 「行程」頁的地圖上**只應該出現 visit（實訪）任務**，phone（電話）任務不該出現在地圖上、只出現在左邊的電話清單。
2. 找一張缺座標的任務（順心診所，A003，SPEC 設計成缺值情境）：如果採納它，它不該出現在地圖或實訪清單上（因為沒有 lat/lon），但任務卡本身還在。

## 尚未測試 / 建議你自己重點看的地方

- **結果回報頁的「結果類型」下拉選單**：我自己用瀏覽器自動化工具測試時，這個下拉選單（Streamlit 的 selectbox）沒辦法穩定用程式操作展開選項（環境限制，不是code bug），所以 completed + 選填結果類型 這條路徑只在單元測試（`test_state_machine.py`）裡驗證過，**麻煩你自己手動點一次**，確認下拉選單能正常選、送出後狀態真的變成「已完成」。
- **上移／下移調整實訪順序**（行程頁）：邏輯上應該沒問題，但我沒有實際點過按鈕驗證畫面正確更新，建議你測一下。
